# Study Flow — Practice 1

Authors: Néstor Pérez, Pablo Laguna

Resources: **courses** (main), tasks, events, study-sessions, grades, users

## Run it

Requires Node 18+. Nothing else.

```
npm install
npm start          -> open http://localhost:3000
```

While developing, `npm run dev` does the same but restarts the server whenever a file changes (Node 18.11+; each restart resets the data).

Open the site from the server at `http://localhost:3000`, not by double-clicking an HTML file or with a "live server" extension: the pages call the API on the same origin.

Data lives in memory: restarting the server resets it to the seed data. Seed dates are relative to the day the server starts, so there is always something on today's dashboard and schedule.

## Resources

Rules that apply to every resource:

- `id` is generated by the server. An `id` sent by the client is ignored.
- Fields not listed in the table are stripped and never stored.
- Text is trimmed before it is checked. Optional text that is missing or empty is stored as `null`.
- Numbers must be JSON numbers (`45`, not `"45"`). Booleans must be `true` or `false`.
- Dates are `YYYY-MM-DD` and must exist in the calendar. Times are `HH:MM` (24-hour, `00:00`–`23:59`).
- `courseId` must be the id of an existing course.
- `POST` and `PUT` run the same validator. `PUT` replaces the whole item, so optional fields left out go back to their default.

### courses (main resource)

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| code | string | required, 3–10 characters: letters, digits and `-` (e.g. `MAT-201`) |
| name | string | required, 1–60 characters |
| instructor | string | required, 1–60 characters |
| meetingTimes | string \| null | optional, max 80 characters (e.g. `Mon and Wed, 9:00 to 11:00`) |
| credits | number | required, integer from 1 to 12 |
| semester | string | required, one of `fall-2026`, `spring-2027` |
| color | string | required, one of `blue`, `green`, `red`, `violet` |
| archived | boolean | optional, defaults to `false` |

### tasks

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| title | string | required, 1–100 characters |
| courseId | number | required, id of an existing course |
| type | string | required, one of `assignment`, `exam`, `project`, `personal`, `quiz`, `study`, `reading` |
| priority | string | required, one of `low`, `medium`, `high` |
| dueDate | string | required, `YYYY-MM-DD` |
| dueTime | string \| null | optional, `HH:MM` |
| reminder | string | optional, one of `none`, `1-day`, `3-days`, `1-week`; defaults to `none` |
| description | string \| null | optional, max 500 characters |
| completed | boolean | optional, defaults to `false` |

### events

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| title | string | required, 1–80 characters |
| type | string | required, one of `class`, `study`, `exam`, `deadline` |
| date | string | required, `YYYY-MM-DD` |
| startTime | string | required, `HH:MM` |
| endTime | string \| null | optional, `HH:MM`, later than `startTime` |
| location | string \| null | optional, max 80 characters |
| courseId | number \| null | optional, id of an existing course |

### study-sessions

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| courseId | number | required, id of an existing course |
| date | string | required, `YYYY-MM-DD` |
| minutes | number | required, integer from 5 to 600 |
| done | boolean | optional, defaults to `false` (`false` = planned, `true` = completed) |
| notes | string \| null | optional, max 200 characters |

### grades

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| courseId | number | required, id of an existing course |
| title | string | required, 1–80 characters |
| score | number | required, from 0 to 100 (decimals allowed) |
| weight | number | required, percentage from 0 to 100 |
| type | string | required, one of `exam`, `assignment`, `project`, `quiz` |
| date | string | required, `YYYY-MM-DD` |

### users

| Field | Type | Rules |
| --- | --- | --- |
| id | number | server-generated, ignored if sent |
| name | string | required, 1–60 characters |
| email | string | required, valid email format, max 100 characters |
| university | string \| null | optional, max 80 characters |
| degree | string \| null | optional, max 80 characters |
| weeklyGoal | number | optional, integer from 1 to 80 (hours); defaults to `15` |
| dailyGoal | number | optional, integer from 1 to 12 (hours); defaults to `2` |
| theme | string | optional, one of `light`, `dark`, `system`; defaults to `system` |
| language | string | optional, one of `en`, `es`; defaults to `en` |

No passwords are stored: the brief does not require authentication.

Deleting a course also deletes its tasks, events, study sessions and grades, so no item points to a course that no longer exists.

Common behaviour:

- `GET /api/courses` filters combine. `search` is a case-insensitive match on `name` or `code`. `semester` must be one of the closed-set values and `archived` must be `true` or `false`; any other value returns `400`.
- `GET /api/courses/stats` is computed on every request, never stored.
- `201` responses include a `Location` header, e.g. `Location: /api/courses/5`, and the created item in the body.
- `204` responses have an empty body.
- A `400` from a validator lists every problem at once: `{ "errors": [ { "field", "message" } ] }`. A body that is not valid JSON also returns `400`.
- An `:id` that does not exist (or is not a number) returns `404 { "error": "Not found" }`.
- Unknown routes return `404 { "error": "Not found" }`. Unexpected errors return `500 { "error": "Internal server error" }`, never a stack trace.

## Postman

`postman/studyflow.postman_collection.json` (Collection v2.1) covers the full CRUD of the main resource, `courses`.

1. Start the server with `npm start`. Restart it before each run so it starts from the seed data.
2. In Postman: **Import** → choose `postman/studyflow.postman_collection.json`.
3. Open the collection → **Run** (Collection Runner) → **Run Study Flow API**. The requests must run in this order:

| # | Request | Expected |
| --- | --- | --- |
| 1 | `POST {{baseUrl}}/courses` | `201` + `Location`; saves the new id in `{{courseId}}` |
| 2 | `GET {{baseUrl}}/courses` | `200`, includes the new course |
| 3 | `GET {{baseUrl}}/courses/{{courseId}}` | `200` |
| 4 | `PUT {{baseUrl}}/courses/{{courseId}}` | `200`, every field replaced |
| 5 | `DELETE {{baseUrl}}/courses/{{courseId}}` | `204` |
| 6 | `GET {{baseUrl}}/courses/{{courseId}}` | `404` (it was deleted) |
| 7 | `POST {{baseUrl}}/courses` with invalid data | `400` with the full `errors` array |
| 8 | `GET {{baseUrl}}/courses?search=CALC&semester=fall-2026&archived=false` | `200`, filtered |
| 9 | `GET {{baseUrl}}/courses?semester=winter&archived=maybe` | `400` |
| 10 | `GET {{baseUrl}}/courses/stats` | `200` |

The collection variable `baseUrl` is `http://localhost:3000/api`. Each request has tests that check its status code and body, so the runner shows a pass or fail for every step.

## Front end

Express serves the pages from `public/`. `public/js/api.js` holds `apiRequest(method, path, body)`, the only place that calls `fetch`. It checks `response.ok` and throws an error carrying the server's `errors` list. `public/js/ui.js` has the shared helpers: loading / error / empty messages, errors shown next to each field, and dates. Each page has its own script:

| Page | Script | Endpoints it calls |
| --- | --- | --- |
| `index.html` (dashboard) | `dashboard.js`, `tasks.js` | `GET /api/users`, `/api/courses`, `/api/tasks`, `/api/events`, `/api/study-sessions`, `/api/grades`; `PUT /api/tasks/:id` (tick a priority task); `POST /api/tasks` (Add-task popup) |
| `courses.html` | `courses.js` | `GET /api/courses?search=&semester=&archived=` (search box, semester select, Active/Archived tabs); `GET /api/courses/stats` (summary under the heading); `POST`, `PUT`, `DELETE /api/courses`; `GET /api/tasks`, `GET /api/grades` (card details); `POST`, `PUT`, `DELETE /api/grades` (detail dialog) |

`main.js` runs on every app page and has no API calls: sidebar, popup open/close, notifications popover and the Weekly/Daily switch.

Lists that are not resources are fixed `<select>` lists or buttons in the HTML, using exactly the values the validators accept: task type, priority and reminder; course semester and colour; event type; grade type; theme and language. Courses are a resource, so every course select is filled from `GET /api/courses`.

Without login, the app treats the first user as "you" (dashboard greeting, weekly goal, settings). Study streak, grade trend, insights, the activity heatmap and the dashboard mini calendar are still static decoration.

## Design decisions

- **Invalid query parameters are rejected with `400`, not ignored.** If `?archived=yes` were ignored, the client would get every course and believe the filter worked. A `400` with the same `{ errors }` shape as the validators makes the mistake visible. Query parameters the API does not know are ignored.
- **`express.static` is mounted in `app.js` after the logger and JSON parser and before the `/api` routers.** Page requests are logged like API calls. Pages and API never share a path (`/courses.html` vs `/api/courses`), so the order between them does not change behaviour. Both come before the JSON 404 and the error handler, which must be last.
- **Searching and filtering happen on the server.** The client only sends the query string and shows what comes back. The browser never has to download every item to filter it, and the rule for what matches lives in one place that every client (the pages, Postman) shares.
- **Validators check shape; controllers check that `courseId` exists.** A validator only looks at the request body. Whether a course with that id exists depends on the stored data, so the controller checks it (`controllers/courseCheck.js`) and adds the problem to the same error list, so every error still comes back at once.
- **Deleting a course deletes its tasks, events, study sessions and grades.** Otherwise those items would point to a course that no longer exists.
- **The store hands out copies.** `store.js` returns copies of its objects, so a controller can't change stored data by accident. Only the store's functions change the arrays, which is what lets a database replace it later.
- **`PUT` replaces the whole item.** It runs the same validator as `POST`, so optional fields that are left out go back to their defaults.
