# Study Flow — Practice 1

Authors: Néstor Pérez, Pablo Laguna

Resources: **courses** (main), tasks, events, study-sessions, grades, users

## Run it

Requires Node 18+. Nothing else.

```
npm install
npm start          -> open http://localhost:3000
```

Data lives in memory: restarting the server resets it to the seed data.

## Resources

Rules that apply to every resource:

- `id` is generated by the server. An `id` sent by the client is ignored.
- Fields not listed in the table are stripped and never stored.
- Text is trimmed before it is checked. Optional text that is missing or empty is stored as `null`.
- Numbers must be JSON numbers (`45`, not `"45"`). Booleans must be `true` or `false`.
- Dates are `YYYY-MM-DD` and must exist in the calendar. Times are `HH:MM` (24-hour, `00:00`–`23:59`).
- `courseId` must be the id of an existing course.
- `POST` and `PUT` run the same validator. `PUT` replaces the whole item, so optional fields left out go back to their default.

Deleting a course also deletes its tasks, events, study sessions and grades, so no item points to a course that no longer exists.

Common behaviour:

- `GET /api/courses` filters combine. `search` is a case-insensitive match on `name` or `code`. `semester` must be one of the closed-set values and `archived` must be `true` or `false`; any other value returns `400`.
- `GET /api/courses/stats` is computed on every request, never stored.
- `201` responses include a `Location` header, e.g. `Location: /api/courses/5`, and the created item in the body.
- `204` responses have an empty body.
- A `400` from a validator lists every problem at once: `{ "errors": [ { "field", "message" } ] }`. A body that is not valid JSON also returns `400`.
- An `:id` that does not exist (or is not a number) returns `404 { "error": "Not found" }`.
- Unknown routes return `404 { "error": "Not found" }`. Unexpected errors return `500 { "error": "Internal server error" }`, never a stack trace.

## Design decisions

- **Invalid query parameters are rejected with `400`, not ignored.** If `?archived=yes` were ignored, the client would get every course and believe the filter worked. A `400` with the same `{ errors }` shape as the validators makes the mistake visible. Query parameters the API does not know are ignored.
- **`express.static` is mounted in `app.js` after the logger and JSON parser and before the `/api` routers.** Page requests are logged like API calls. Pages and API never share a path (`/courses.html` vs `/api/courses`), so the order between them does not change behaviour. Both come before the JSON 404 and the error handler, which must be last.
- **Searching and filtering happen on the server.** The client only sends the query string and shows what comes back. The browser never has to download every item to filter it, and the rule for what matches lives in one place that every client (the pages, Postman) shares.
